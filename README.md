# focuspin AI — бекенд

OpenAI-chat-completions-совместимый фасад над DeepSeek для мобильного
приложения focuspin. Приложение присылает свой «магический» запрос обычным
языком, бекенд возвращает **только** валидный канонический JSON команд
планировщика — сырой текст модели наружу не выходит никогда. Ноль runtime-
зависимостей, хранилище — `bun:sqlite`.

## Как это работает

```
приложение focuspin
   │  POST /v1/chat/completions
   │  Authorization: Bearer <deviceId>
   ▼
пин системного промпта → лимиты (HMAC-хеши device id/IP) → DeepSeek
   ▼
гард валидации команд → канонический JSON в choices[0].message.content
```

Единственный продуктовый путь — `POST /v1/chat/completions` (формат тела и
ошибок — [contract/api.md](contract/api.md)). Ответ 200 — форма OpenAI
`chat.completion`, содержательное поле одно: `choices[0].message.content` —
строка `{"commands":[...]}` после гарда. Заголовок `x-focuspin-contract:
commands-v4` — версия контракта.

## Почему это безопасно

- **Пин промпта.** Сервер не проксирует произвольные запросы: системное
  сообщение обязано побайтово совпасть с закреплённым промптом v4, иначе 400.
  Приложение не может попросить модель ни о чём другом.
- **Гард валидации.** Ответ модели проходит строгую схему команд
  (`contract/schema-v4.md`) и каноническую пересборку; мусор, prose, markdown
  и посторонние поля до приложения не доходят (в худшем случае — 502
  `contract_violation`).
- **Никаких секретов у клиента.** Ключ DeepSeek живёт только на бекенде;
  device id — не секрет, а merely идентификатор.
- **Приватность.** В БД и логах нет сырых device id и IP — только
  HMAC-хеши; содержимое сообщений не логируется.
- **Предохранители расходов.** Глобальные дневные потолки запросов и токенов
  не дают атаке сжечь ключ DeepSeek даже в худшем случае.

## Ярусы лимитов (дефолты)

| Ярус | Лимит | Что отсекает |
|---|---|---|
| IP / минута | 15 | Лобовая атака с одного адреса |
| IP / час | 60 | Скриптовый перебор |
| IP / сутки | 300 | Фоновый абьюз |
| Подсеть /24 · /64 / сутки | 1200 | Ботнет из одной сети |
| Разные device id с одного IP / сутки | 6 | Ротация идентификаторов |
| Устройство / минута | 6 | Долбёжка кнопкой |
| Устройство / час | 15 | Активный абьюз |
| Устройство / сутки | 50 | Норма на устройство |
| Свежее устройство (< 24 ч) / сутки | 15 | Делает ротацию невыгодной |
| Contract fail / устройство / час | 10 | Систематическая порча контракта |
| Глобально: в полёте | 8 | Перегрузка upstream (429 `busy`) |
| Глобально: запросы / сутки | 20000 | Потолок расходов на ключ |
| Глобально: токены / сутки | 25 000 000 | Потолок расходов на ключ |

Окно «сутки» — UTC. Отказ — 429 `rate_limited` с `Retry-After`. Все пороги
переопределяются env-переменными (`LIMIT_*`, `GLOBAL_*` — см.
[.env.example](.env.example) и [ops/DEPLOY.md](ops/DEPLOY.md)).

## Идентификация без аккаунта

Устройство identifies себя 32-hex `deviceId` (создаётся приложением локально,
опционально с суффиксом `_<счётчик>` ротации). Учёт ведётся по
HMAC-хешам device id и IP: сервер помнит «первое появление» устройства —
молодым устройствам суточная квота понижена (15 против 50), а с одного IP за
сутки учитывается не более 6 разных устройств. Итог: аккаунт не нужен,
анонимность сохранена, а дешёвая ротация идентификаторов смысла не имеет.

## Быстрый старт

```bash
bun install
cp .env.example .env        # для разработки подойдёт как есть
bun run dev                 # сервер на :8080 (нужен стаб DeepSeek — см. ниже)
bun test                    # 189 юнит- и golden-тестов
bun run smoke               # end-to-end самопроверка реального сервера
```

Для локальной разработки без ключа DeepSeek поднимите стаб (он же участвует
в smoke):

```bash
bun run scripts/stub-deepseek.ts     # :8901, режимы STUB_MODE=valid|garbage|slow
DEEPSEEK_BASE_URL=http://127.0.0.1:8901/v1 bun run dev
```

Генератор нагрузки:

```bash
bun run scripts/load.ts --url http://127.0.0.1:8080 --duration-sec 30 --rps 20
```

## Структура репозитория

| Путь | Что там |
|---|---|
| `src/` | Код: `api/` роутер, `contract/` гард команд, `identity/` HMAC, `limiter/` ярусы, `llm/` пайплайн и DeepSeek, `server.ts`, `main.ts` |
| `contract/` | HTTP-контракт (`api.md`), схема команд v4, golden-фикстуры парсера |
| `scripts/` | `stub-deepseek.ts` (стаб upstream), `smoke.ts` (e2e), `load.ts` (нагрузка) |
| `ops/` | Dockerfile, docker-compose, Caddyfile, systemd-юнит, [DEPLOY.md](ops/DEPLOY.md) |

Контракт зеркалит приложение: `contract/schema-v4.md` ↔
`lib/magic_input/task_command.dart` + `magic_response_parser.dart`, промпт
`src/llm/prompt.ts` ↔ `lib/magic_input/magic_prompt.dart`. Менять — синхронно
в обоих репозиториях.
